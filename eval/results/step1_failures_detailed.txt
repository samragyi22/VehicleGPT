              to find_largest_change for speed trends.

          a control command (is_control_command should return True), but the model
          output overrides the guard. The guard returns a status, but if the model
          still produces a tool call, it gets routed. This may be a prompt issue
          where the model doesn't respect the control command boundary.

Improvement: +3 questions for 0.5B (+7.5 percentage points)

Root cause of improvement: The deterministic override (why→explain_factors) was
changing the tool but not cleaning the args dict, so 'reason' (from out_of_scope)
was being passed to explain_factors, which doesn't accept that field. This caused
validation errors. The bugfix (commit 0462e4e) clears args when overriding tools.
